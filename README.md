# 폰트공방 — 손글씨로 만드는 나만의 한글 폰트

종이 템플릿에 손글씨를 쓰고 휴대폰으로 찍으면, 현대 한글 11,172자가 모두 들어간 TTF 폰트를 만들어 주는 웹앱입니다.
모든 처리는 브라우저 안에서 끝납니다. 서버가 필요 없고, 사진은 기기 밖으로 나가지 않습니다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # dist/ 에 정적 사이트 생성
```

## 배포 (GitHub + Vercel)

1. 이 폴더를 GitHub 저장소로 올립니다.
2. Vercel에서 저장소를 가져오면 Vite로 자동 인식됩니다. 설정을 바꿀 필요가 없습니다.
3. 카메라는 HTTPS에서만 열리므로 Vercel 주소(https)로 접속해 쓰세요.
4. **갤러리를 쓰려면** Vercel 프로젝트의 Storage 탭에서 Blob 저장소를 만들어 이 프로젝트에 연결하세요. `BLOB_READ_WRITE_TOKEN`이 자동으로 생기고, 다시 배포하면 갤러리가 켜집니다. 연결 전에는 갤러리에 “저장소가 아직 연결되지 않았어요”가 보이고 폰트 만들기는 그대로 됩니다.
5. (선택) 환경 변수 `GALLERY_ADMIN_TOKEN`에 긴 비밀 문자열을 넣으면, 그 브라우저에서 `주소/#gallery?admin=비밀문자열`을 한 번 열어 다른 사람이 올린 글씨체도 내릴 수 있습니다.

### 갤러리 저장 방식

| 실행 환경 | 저장소 | 내 글씨체 알아보기 | 관리 |
| --- | --- | --- | --- |
| Vercel 배포 | `api/fonts.ts` → Vercel Blob (`gallery/fonts`, `gallery/previews`, `gallery/meta`) | 올릴 때 받은 삭제 열쇠를 그 브라우저에 보관 | `GALLERY_ADMIN_TOKEN` |
| claude.ai 미리보기 | 페이지 데이터베이스 `gallery/<사용자>` + 파일 저장소 | 로그인한 사용자 | 페이지 주인 |

원본 사진은 어디에도 올라가지 않습니다. 공개를 고르면 TTF 파일과 견본 그림(PNG)만 올라갑니다.

## 엔진 (`src/engine`)

| 파일 | 역할 |
| --- | --- |
| `sheet.ts` | ArUco 마커 → 호모그래피로 시트 펴기 → 하늘색 안내선 제거 → 조명 보정·이진화 → 칸 판정(빈 칸, 건너뛰기 ○, 칸 밖) |
| `refmask.ts` | 기준 글꼴(Pretendard)로 음절별 초·중·종 영역 지도 생성. 대조 글자와 겹쳐 보고, 위치만 옮겨 그려진 획(ㅓ·ㅕ의 짧은 획, 초성 높이에 따라 오르내리는 ㅡ, 받침에 따라 움직이는 윗부분)은 덩어리마다 위치를 맞춰 되돌린다 |
| `segment.ts` | 손글씨 획 덩어리를 초·중·종에 배치하는 탐색 (상대 위치 + 자모 모양 + 잉크 비율), 신뢰도 점수. 점수가 나쁘면 `strokes.ts`의 획 조각 단위로 다시 찾는다 |
| `strokes.ts` | 뼈대(세선화)를 갈림점·꺾이는 곳에서 끊어, 붙여 쓴 자모를 획 조각으로 나눈다 |
| `consensus.ts` | 같은 자모 샘플끼리 모양을 비교해 잘못 잘린 샘플을 찾는다 (조합에서 빼고, 04 단계에 표시) |
| `model.ts` | 자모 샘플 라이브러리. 같은 꼴(8·4·4벌)·모양의 전형성·분리 신뢰도·문맥을 함께 따져 샘플을 고른다. 사용자 글씨에서 배우는 자모 위치(개인화 레이아웃), 쌍자음·겹받침 합성 |
| `vectorize.ts` | 비트맵 → 윤곽 → TrueType 2차 B-스플라인 |
| `ttf.ts` | TTF 작성기. 조합 글자는 자모 글리프를 참조하는 복합 글리프라 11,172자가 1MB 안팎 |
| `build.ts` | 위 단계를 묶어 폰트 한 벌 생성 (굵기·자간 옵션, 같은 글자는 나중 시트가 이김). 줄여 넣은 자모는 획을 굵혀 굵기를 맞추고, 한글 글리프를 칸 가운데로 모아 글자 사이를 고르게 한다 |
| `punct.ts` | 쓰지 않은 기본 문장부호 13개를 내 펜 굵기와 글자 높이에 맞춰 그림 |
| `supplement.ts` | 보충 시트 PDF를 브라우저에서 직접 그림 (마커·QR·칸, 80자마다 한 장) |
| `cv.ts` | 영상 처리 엔진(12MB) 받기와 진행률 |

`src/data/template-layout.json`에 템플릿 칸 좌표(mm)가 들어 있습니다. 템플릿을 바꾸면 이 파일과 PDF를 함께 바꾸세요.

## 검증한 것

- 가상 손글씨 사진(원근 기울임·그림자·잡음·JPEG)으로 빠른 폰트와 표준 폰트를 처음부터 끝까지 생성
- 생성 TTF는 fontTools로 열리고 OTS(크롬이 쓰는 폰트 검사기)를 통과
- 자모 분리: 자모별로 비율을 비튼 합성 정답 225자 기준 화소 정확도 약 95.6%

## 알려진 한계 (다음 버전)

- 빠른 폰트에는 영문이 없어 앱의 기본 글꼴로 대체됩니다 (기본 문장부호는 자동으로 그리고, 표준 폰트에는 영문 포함)
- 자모가 위아래로 쌓이는 글자(은, 를, 훑)의 자동 분리가 상대적으로 약합니다 → 04 단계에서 눌러 고치기
- OTF·WOFF2 내보내기, 계정·보관함, 학급 모드는 PRD의 P1·P2 범위입니다

## 테스트 도구 (`tests/`)

- `ttf-smoke.ts`: TTF 작성기 단독 검사 (`npx tsx tests/ttf-smoke.ts`)
- `synth.py`, `e2e.py`: 가상 사진 생성과 화면 전체 자동 시험 (Playwright 필요)
- `api-test.ts`: 갤러리 API 단위 시험 (`node --experimental-strip-types tests/api-test.ts`)
- `devserver.ts`: dist + 메모리 갤러리 API 시험 서버 (포트 4180)
- `v12.py`: 굵기·자간, 자동 문장부호, 보충 시트(PDF→합성 손글씨→업로드→교체), 갤러리 공개·검색·내리기·관리자
- `real.html`, `realrun.py`, `compare.py`, `segsheet.py`, `groupsheet.py`, `metric.py`: 실제 사용자 폰트(`tests/user.ttf`, 저장소에 올리지 않음)의 직접 쓴 글자를 칸 그림으로 되돌려 자모 분리·조합을 다시 돌려 보고 비교하는 도구 (`npx vite --port 5179` 후 실행)
- `reseg.py`: 예전 방식으로 나눈 프로젝트를 이어서 하면 새 방식으로 다시 나누는지
- `artifact-mock.py`: claude.ai 미리보기 환경(데이터베이스·파일 저장소)을 흉내 낸 갤러리 시험
- `seg.html`, `evalsynth.py`: 자모 분리 정확도 측정 (`npm run dev -- --port 5179` 후 실행)
